# Run Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (the owner runs TDD plans inline). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a run opens on a page of its own that says everything the log said about it — how it ended and what killed you, the route floor by floor with the floors' names, the items with three more ways to read them — and the list shows each character's face.

**Architecture:** `catalog` names a floor from the game's `stages.xml` + `stringtable.sta` through a hand table from the log's `(m_Stage, m_StageType)`; the `run` fold keeps each pickup's pool and floor and the death's spawner (rules version 4 → 5, the archive refolds itself); `ipc::RunView` carries the floors, the pickups, the killer resolved to an entity, and the face; the Runs screen picks list or page from a `run` query, like the Wiki screen, and both bodies scroll as a page.

**Tech Stack:** Rust (quick-xml via `catalog::xml`, serde, ts-rs), Vue 3 + TypeScript, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-04-run-page-design.md`

## Global Constraints

- No path or offset crosses the IPC; a run is addressed by its key, a launch by its row id.
- Every struct on the wire `rename_all = "camelCase"`; enums with struct variants also `rename_all_fields`.
- No `_ =>` on a closed enum; no `unwrap()` on disk data outside tests.
- A reference carrying an id is resolved by the id first (the face by `character_id`).
- Never a guessed name: a floor whose name has no source shows its numbers.
- `samples/` is opened only through `test-support`; nothing writes under it. `samples/packed` in a worktree is a junction to the game: remove it with `[System.IO.Directory]::Delete(path, $false)` before the worktree goes.
- Frontend: no `<style>`, no hardcoded visual constants, no raw `<button>`, no `invoke()` outside `lib/ipc/`, const objects not string unions, every visible string through i18n (`it` and `en`).
- Commits: `type(scope): subject`, staged by explicit path, no co-author trailer, **never `--no-verify`**.

## Review Focus

1. **An archive folded by rules 4** — cached runs carry the old `collected: [u32]` shape: they must refold, never fail to read and vanish. Task 2 tests that a v4 cache is stale under v5.
2. **A killer that is a projectile** (`9.0` spawned by `84.0`) — the line must name the spawner, not "Projectile": Task 3 tests a `9.0`/`84.0` death.
3. **A spawner `0.0`** — nobody: no "spawned by" at all. Task 3.
4. **A floor pair outside the hand table** (Greed's floors, a new DLC stage) — numbers, never a borrowed name: Task 1.
5. **A `run` query that matches no run** — the "no such run" page with a way back, not the list and not a blank: Task 5.

```rust
//! `stages.xml`: one row per stage *file*, keyed by the game's own stage id, its `name` a string
//! key (`#BASEMENT_NAME`). The log does not use those ids: it writes `m_Stage, m_StageType`, and
//! the table below is the link. Measured on 2026-09-04's install, 2026-10-04: ids 1–17 the
//! original floors, 26 The Void, 27–33 the Repentance alternates, 35 Home; the greed stages
//! 18–25 sit inside an XML comment.

use std::collections::BTreeMap;

use crate::diagnostics::{Diagnostic, Source};
use crate::text::Text;
use crate::xml;

const SOURCE: Source = Source::Stages;

pub fn parse(bytes: &[u8], diagnostics: &mut Vec<Diagnostic>) -> BTreeMap<u32, Text> {
    let Some(els) = xml::read(bytes, SOURCE, diagnostics) else {
        return BTreeMap::new();
    };
    els.iter()
        .filter(|e| e.name == "stage")
        .filter_map(|e| Some((e.attr("id")?.parse().ok()?, Text::from_attr(e.attr("name")?))))
        .collect()
}

/// The `stages.xml` id the log's `(m_Stage, m_StageType)` names, and whether the floor is one of
/// a chapter's two. Not in any game file: the game's own enumeration, as the modding API documents
/// it — `LevelStage` 1–13, `StageType` 0 original, 1 Wrath of the Lamb, 2 Afterbirth,
/// 4 Repentance, 5 Repentance B. Held against the one measured pair, `4, 4` = Mines II.
pub fn file_of(stage: u32, stage_type: u32) -> Option<(u32, bool)> {
    let chapter = |base: u32, alt: u32, burnt: u32, rep: u32, rep_b: u32| match stage_type {
        0 => Some(base),
        1 => Some(alt),
        2 => Some(burnt),
        4 => Some(rep),
        5 => Some(rep_b),
        _ => None,
    };
    let id = match stage {
        1 | 2 => chapter(1, 2, 3, 27, 28)?,
        3 | 4 => chapter(4, 5, 6, 29, 30)?,
        5 | 6 => chapter(7, 8, 9, 31, 32)?,
        7 | 8 => match stage_type {
            0 => 10,
            1 => 11,
            2 => 12,
            4 => 33,
            _ => return None,
        },
        9 => 13,
        10 => if stage_type == 1 { 15 } else { 14 },
        11 => if stage_type == 1 { 17 } else { 16 },
        12 => 26,
        13 => 35,
        _ => return None,
    };
    Some((id, (1..=8).contains(&stage)))
}
```

Then in `catalog.rs`: `Source::Stages => "stages.xml"` in `path_of`, the `SOURCES` array grows to 15, `Catalog` gains `stages: BTreeMap<u32, Text>` built in `build` with `src.parse(Source::Stages, stages::parse)`, and:

```rust
    /// A floor's name as the game writes it, from the log's `m_Stage, m_StageType`: `None` when
    /// any link is missing — the pair is not in the table, the file or the string is not there.
    pub fn floor_name(&self, stage: u32, stage_type: u32) -> Option<String> {
        let (id, numbered) = stages::file_of(stage, stage_type)?;
        let name = match self.stages.get(&id)? {
            Text::Key { key } => self.strings.as_ref()?.get(key, Language::English)?,
            Text::Literal { text } => text.as_str(),
        };
        Some(if numbered {
            format!("{name} {}", if stage % 2 == 1 { "I" } else { "II" })
        } else {
            name.to_string()
        })
    }
```
