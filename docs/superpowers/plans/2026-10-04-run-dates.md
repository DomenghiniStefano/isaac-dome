# Run dates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (the owner runs TDD plans inline). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every run on the Runs screen carries a day — a session from its folder name, a `log.txt` launch from the file's modification time — and past launches stop collapsing into "live".

**Architecture:** migration 7 adds `sources.written_unix`; `log-watch` stamps it on every read of `log.txt`; `ipc::RunSource` gains `Launch { id, writtenUnix }` and `Live { writtenUnix }`, the store deciding which by "is this the latest launch"; the UI parses session names as local time, orders sessions and past launches together by date, and draws a Date column with the time in a tooltip.

**Tech Stack:** Rust (rusqlite, serde, ts-rs), Vue 3 + TypeScript, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-04-run-dates-design.md`

## Global Constraints

- The column is `written_unix INTEGER`, nullable, epoch **seconds**; migration 7, additive, never rewrites a row.
- A missing mtime never erases a stored one: `written_unix = COALESCE(?, written_unix)`.
- The date and the offset move in **one transaction** (`append_to_log`).
- No path or offset crosses the IPC; the launch `id` is the source's row id, opaque.
- Enums on the IPC: `tag = "kind"`, `rename_all = "camelCase"`, `rename_all_fields = "camelCase"`.
- No `_ =>` on a closed enum; no `unwrap()` outside tests on disk data.
- A screen never writes its own `Intl.DateTimeFormat`: formatters live in `ui/src/lib/profile/profileView.ts` and are reached through `useFormat`.
- No hardcoded visual constants in templates: a new width is a token in `ui/src/assets/theme/spacing.css`.
- Every visible string goes through i18n, `it` and `en` both.
- Commits: Conventional Commits, scope = crate or `ui`, no co-author trailer, staged by explicit path.

**Deviation from the spec, decided while planning:** the day is printed with the existing `formatDate` (`3 Oct 2026`), not `Sat 3 Oct` — `profileView.ts` is "the one date shape the interface prints", and a second shape would be the thing that rule forbids. `insert_log_source` keeps its signature: `live_log` always follows it with `append_to_log` in the same pass, which carries the date.

## Review Focus

1. **A launch resumed across a migration** — the latest pre-migration launch must pick up a date on its next `Continue`, older ones stay `NULL`: Task 1 tests `COALESCE` and `NULL` rows; Task 2 tests the stamp on a resume.
2. **A session folder name parsed as local time** — `09_12_2026__13_34_26` must display 13:34 in any zone: Task 4 asserts `getHours() === 13`, not an epoch.
3. **Two launches' first runs** — distinct keys and distinct facet value: Task 4.
4. **An undated launch among dated sessions** keeps its archive position, never sorted to an end: Task 4.
5. **A file whose mtime the OS will not give** — the ingest still succeeds and the stored date stays: Task 1 (`None` keeps the date) and Task 2 (`modified` is `Option`).

```rust
/// When the file was last written, in epoch seconds, or `None` when the OS cannot say. Never an
/// error: a date is not worth failing an ingest over.
pub fn modified(path: &Path) -> Option<i64> {
    let at = std::fs::metadata(path).ok()?.modified().ok()?;
    let secs = at.duration_since(UNIX_EPOCH).ok()?.as_secs();
    i64::try_from(secs).ok()
```

```rust
impl StoredSource {
    /// The source as the Runs screen names it. A session row with no name cannot be told from
    /// a launch, and the launch is the honest reading: it is the source with no name. Of the
    /// launches, only `latest_log` is Live — the rest are past launches, each its own source.
    pub fn run_source(&self, latest_log: Option<i64>) -> RunSource {
        match (self.kind, &self.key) {
            (SourceKind::Session, Some(name)) => RunSource::Session { name: name.clone() },
            (SourceKind::Session, None) | (SourceKind::Log, _) => self.launch(latest_log),
        }
    }

    fn launch(&self, latest_log: Option<i64>) -> RunSource {
        let written_unix = self.written_unix;
        if latest_log == Some(self.id) {
            RunSource::Live { written_unix }
        } else {
            RunSource::Launch {
                id: self.id,
                written_unix,
            }
        }
    }
}
```

```ts
/**
 * The instant a session's folder name states, or `null` when the name is not one — a
 * `desyncs` folder, a name from another tool, a rename by hand. **Local time**: the name is
 * the player's wall clock, and the hour it is shown with must be the hour it says.
 */
export const sessionTime = (name: string): number | null => {
  const m = SESSION_NAME.exec(name)
  if (m === null) return null
  const [month, day, year, hour, minute, second] = m.slice(1).map(Number)
  const at = new Date(year, month - 1, day, hour, minute, second)
  // `Date` accepts a 13th month by rolling over; a name that rolls over is not a name we
  // read, it is a name we guessed at.
  const rolled = at.getMonth() !== month - 1 || at.getDate() !== day
  return rolled ? null : at.getTime()
}

/** When a run's source is dated, in epoch ms, or `null` when it carries no date. */
export const runTime = (run: RunView): number | null => {
  switch (run.source.kind) {
    case 'session':
      return sessionTime(run.source.name)
    case 'live':
    case 'launch':
      return run.source.writtenUnix === null ? null : run.source.writtenUnix * 1000
    default:
      return assertNever(run.source)
  }
}

/** Every run of one source keeps its own place; a source is ordered once. */
const sourceKey = (run: RunView): string => sourcePart(run.source)
```

```ts
import type { RunView } from '@/lib/ipc/types'
import { runTime } from './runOrder'

// What a run's date *is*, and not only when: a session is dated by when it started and a launch
// by when its file was last written. Shown side by side they would read as the same thing, so
// the kind travels with the instant and the tooltip names it.
export const RunDateKind = {
  Started: 'started',
  Written: 'written',
  Undated: 'undated',
} as const
export type RunDateKind = (typeof RunDateKind)[keyof typeof RunDateKind]

export type RunDate =
  | { kind: typeof RunDateKind.Started; at: Date }
  | { kind: typeof RunDateKind.Written; at: Date }
  | { kind: typeof RunDateKind.Undated }

export const runDate = (run: RunView): RunDate => {
  const time = runTime(run)
  if (time === null) return { kind: RunDateKind.Undated }
  const at = new Date(time)
  return run.source.kind === 'session'
    ? { kind: RunDateKind.Started, at }
    : { kind: RunDateKind.Written, at }
}
```
