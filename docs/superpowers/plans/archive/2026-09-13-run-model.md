# M4 sub-project 1a — the run model — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pure `run` crate that turns the lines of `log.txt` into typed events and folds them
into a run — what was played, with what, and how it ended — with no disk, no database and no
screen anywhere near it.

**Architecture:** Three pieces, in dependency order. `Tail` turns bytes into complete lines and
recognizes a relaunch. `Rules` — a versioned JSON file of regexes, embedded at build time like
`graph`'s — maps a line to an `Event` and does nothing else. `Run::fold` holds every judgment:
which item was the character's starting gift, which actives were replaced, what the outcome was
when the log never said. The item kinds the fold needs arrive through a trait the caller
implements, so `run` never depends on `catalog`.

**Tech Stack:** Rust, `serde` + `serde_json` (the rules file), `regex` (already in the
workspace's dependency tree), `test-support` for the real logs.

**Spec:** `docs/superpowers/specs/2026-09-12-m4-run-model-design.md`

## The spec is a day old and three things in it have moved

Corrected in the spec by the commit that lands this plan; repeated here because an executor
reads the plan.

1. **The store migration is the fourth, not the third.** `store::SCHEMA_VERSION` is already 3:
   the window session landed with `feature/background-and-tray` on 2026-09-13. Nothing in *this*
   plan touches `store` — it is 1b's — but the number is wrong wherever it is read.
2. **Every log line carries a prefix the spec's table does not show.** Measured on
   `samples/logs/20260908-run-megasatan-judas.log.txt`: lines read
   `[INFO] - RNG Start Seed: …`, and some carry a frame marker as well —
   `[INFO] - [Frame 74] Starting room transition (type 0)`. About 1% of lines carry no `[INFO] -`
   at all (the `Framebuffer Width:` block B8 found, and library banners). A rule anchored at the
   start of the line matches nothing.
3. **No sample log contains `Game Over`.** All four are wins or open runs, so the `Died` event
   has **no real-data test** — only the line shape recorded in M0 and in `CLAUDE.md`. Task 5
   states that gap out loud rather than letting a green suite imply coverage.

## Global Constraints

- **`run` is pure**: no `std::fs`, no `std::net`, no clock. Anything that reads bytes is 1b's.
- **The rules file maps text to events and makes no judgment.** It is data a user can edit; a
  rule that could decide *meaning* would put untestable logic outside the tested crate.
- **`run` does not depend on `catalog`.** Item kinds arrive through `ItemKinds`, a trait.
- **Never `panic!` or `unwrap()`** outside tests on anything read from a log or a rules file.
- **Exhaustiveness is mandatory**: no `_ =>` on a closed enum.
- **Tests on real data go through `test-support`**, which declares `sample:` or `skip:` on
  stderr. No test opens `samples/logs/` by hand.
- **Test-first**, and the expected value comes from the spec or from a measurement, never from
  the code's current output.
- Commits: Conventional Commits, `type(scope): subject`, English, atomic. No `Co-Authored-By`.

```rust
/// The folder the real logs live in. Git-ignored, like `samples/` itself.
pub fn logs_dir() -> PathBuf {
    samples_dir().join("logs")
}

/// One log by name, declaring on stderr which file it is or why there is none.
pub fn log_sample(name: &str) -> Option<PathBuf> {
    let path = logs_dir().join(name);
    if path.is_file() {
        eprintln!("sample: logs/{name}");
        Some(path)
    } else {
        skip(&format!("logs/{name} missing from samples/logs/"));
        None
    }
}

/// Every real log, in name order. `samples/logs/` also holds probe output and a watcher
/// trace: only `*.log.txt` is a log, and the filter lives here rather than in each test.
pub fn log_samples() -> Vec<PathBuf> {
    let Ok(entries) = std::fs::read_dir(logs_dir()) else {
        skip("samples/logs/ is missing");
        return Vec::new();
    };
    let mut found: Vec<PathBuf> = entries
        .flatten()
        .map(|e| e.path())
        .filter(|p| {
            p.file_name()
                .and_then(|n| n.to_str())
                .is_some_and(|n| n.ends_with(".log.txt"))
        })
        .collect();
    found.sort();
    for path in &found {
        if let Some(name) = path.file_name().and_then(|n| n.to_str()) {
            eprintln!("sample: logs/{name}");
        }
    }
    if found.is_empty() {
        skip("no *.log.txt in samples/logs/");
    }
    found
}
```

```rust
/// The part of tailing a file that has no I/O in it: complete lines out of chunks that do not
/// respect line endings, and the one comparison that says the game relaunched.
#[derive(Debug, Default)]
pub struct Tail {
    remainder: String,
    read: u64,
}

impl Tail {
    /// The complete lines in `chunk`, with whatever was left over from last time in front of
    /// them. A trailing partial line is kept, not returned: it is not a line yet.
    pub fn advance(&mut self, chunk: &[u8]) -> Vec<String> {
        self.read += chunk.len() as u64;
        // Lossy on purpose: a mod can write anything into this file, and one bad byte must not
        // cost the run around it.
        self.remainder.push_str(&String::from_utf8_lossy(chunk));
        let mut lines = Vec::new();
        while let Some(at) = self.remainder.find('\n') {
            let line = self.remainder[..at].trim_end_matches('\r').to_string();
            self.remainder.drain(..=at);
            lines.push(line);
        }
        lines
    }

    /// The file is shorter than what we have read from it: the game relaunched and rewrote it.
    pub fn restarted(&self, len: u64) -> bool {
        len < self.read
    }

    /// Start over on a new file. The old remainder is dropped rather than carried: it would
    /// arrive glued to the first line of the new log.
    pub fn restart(&mut self) {
        self.remainder.clear();
        self.read = 0;
    }
}
```

### Task 3: the rules file, and the nine events

**Files:**
- Create: `crates/run/rules/events.json`, `crates/run/src/event.rs`, `crates/run/src/rules.rs`
- Modify: `crates/run/src/lib.rs`
- Test: `crates/run/tests/rules.rs`

**Interfaces:**
- Produces: `run::Event` (nine variants), `run::Rules` with
  `Rules::embedded() -> Rules`, `Rules::parse(text: &str) -> Result<Rules, RulesError>` and
  `Rules::event(&self, line: &str) -> Option<Event>`. Task 4's fold consumes `Event`.

**The file is JSON holding regexes with named captures**, embedded with `include_str!` the way
`graph` embeds `rules/requirements.json`. A regex rather than a hand-written scanner because the
requirement is that a user can update the patterns without recompiling — and because the room
line alone has three shapes (`Room 1.2(Start Room)`, `Room 1.1075(New Room)`, `Room 4.21()`).

**Every pattern is unanchored**, which is the correction at the top of this plan: real lines
begin `[INFO] - ` and sometimes `[INFO] - [Frame 74] `.

- [ ] **Step 4: Implement**

`crates/run/src/event.rs` holds the enum — nine variants, the fields exactly as the captures
above name them, `#[derive(Debug, Clone, PartialEq, Eq)]`. It is **not** an IPC type: nothing
here derives `Serialize` yet, and 1b decides what crosses.

`crates/run/src/rules.rs` holds:

- `Rules { version: u32, patterns: Vec<(EventKind, Regex)> }`, built from the JSON through a
  `#[derive(Deserialize)]` mirror struct;
- `RulesError` with two variants, `Json(String)` and `Pattern { kind: String, message: String }`
  — a typed error, not a `String`, because 1b reports it to the user when a user-supplied file
  fails and the embedded one takes over;
- `Rules::event` walks the patterns in a fixed order and returns the first match. Order matters
  and the order is the file's: `roomTransition` before `roomEntered` costs nothing, but a
  future pattern that could match two things must be decidable by reading the file.

Parsing a capture that is declared `\d+` and does not fit a `u32` yields `None` for the whole
event rather than a partial one: the line was not what the rule thought it was.

```rust
//! Hand-written event sequences: no log, no game, no catalog. That is the point of the crate
//! being pure.

use run::{Event, ItemKind, ItemKinds, Outcome, Run};

/// The catalog stands in as a table, so a test says which kind each id is.
struct Kinds(&'static [(u32, ItemKind)]);

impl ItemKinds for Kinds {
    fn kind_of(&self, id: u32) -> ItemKind {
        self.0
            .iter()
            .find(|(k, _)| *k == id)
            .map(|(_, v)| *v)
            .unwrap_or(ItemKind::Passive)
    }
}

fn started() -> Event {
    Event::RunStarted {
        seed_words: "YKF6 QDN6".into(),
        seed_numeric: 2_913_253_616,
        kind: "New".into(),
    }
}

fn item(id: u32, character: &str) -> Event {

        id,
        name: format!("item {id}"),
        player: 0,
        character: character.into(),
```

```rust
//! The rules, against logs the game actually wrote. Skips with a note when `samples/logs/` is
//! not there: the folder is git-ignored and the suite stays green for anyone who clones.

use run::{Event, ItemKind, ItemKinds, Outcome, Rules, Run, Tail};

struct AllPassive;

impl ItemKinds for AllPassive {
    fn kind_of(&self, _id: u32) -> ItemKind {
        ItemKind::Passive
    }
}

fn events_of(name: &str) -> Option<Vec<Event>> {
    let path = test_support::log_sample(name)?;
    let bytes = std::fs::read(path).ok()?;
    let rules = Rules::embedded();
    let mut tail = Tail::default();
    Some(tail.advance(&bytes).iter().filter_map(|l| rules.event(l)).collect())
}

#[test]
fn a_real_log_yields_the_events_its_lines_promise() {
    let Some(events) = events_of("20260908-run-megasatan-judas.log.txt") else { return };

    let count = |f: fn(&Event) -> bool| events.iter().filter(|e| f(e)).count();

    assert_eq!(count(|e| matches!(e, Event::FloorEntered { .. })), 10);
    assert_eq!(count(|e| matches!(e, Event::ItemAdded { .. })), 34);
    assert_eq!(count(|e| matches!(e, Event::RoomTransition)), 343);
    assert_eq!(count(|e| matches!(e, Event::AchievementUnlocked { .. })), 2);
    assert_eq!(count(|e| matches!(e, Event::SaveWritten { .. })), 132);
}

#[test]
fn no_sample_log_contains_a_death() {
    // **A gap, asserted so it cannot be forgotten.** All four logs in `samples/logs/` are wins
    // or open runs: `Event::Died` is covered only by `crates/run/tests/rules.rs`, against the
    // line shape recorded in M0, and by the fold's hand-written sequence. When a log with a
    // death arrives this test fails — and that failure is the signal to write the real one.
    let mut with_a_death = Vec::new();
    for path in test_support::log_samples() {
        let Ok(bytes) = std::fs::read(&path) else { continue };
        let rules = Rules::embedded();
        let mut tail = Tail::default();
        if tail
            .advance(&bytes)
            .iter()
            .filter_map(|l| rules.event(l))
            .any(|e| matches!(e, Event::Died { .. }))
        {
            with_a_death.push(path);
        }
    }
    assert!(
        with_a_death.is_empty(),
        "a log with a death exists now: write the real test for it — {with_a_death:?}"
    );
}
```
